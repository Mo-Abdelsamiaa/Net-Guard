## 📌 What This Project Does

NetGuard is a lightweight, Python-based **Network Intrusion Detection System (NIDS)**
that monitors network traffic — either live or from a saved `.pcap` file — and
automatically detects three common malicious traffic patterns that a SOC analyst
watches for every day:

| # | Detection | What It Represents |
|---|-----------|---------------------|
| 1 | **Port Scanning** | An IP probing many different destination ports in a short time window (e.g. `nmap` reconnaissance) |
| 2 | **ICMP Flood** | An abnormal volume of ping (ICMP) packets from a single source — a simple Denial-of-Service pattern |
| 3 | **Brute-Force Pattern** | Repeated rapid connection attempts to the *same* port (e.g. SSH/RDP credential brute-forcing) |

Every detection is:
- Printed live to the console as a real-time **alert** (like a SIEM dashboard would)
- Written to a structured **log file** (JSON or CSV) with timestamp, source IP, and details

This mirrors the core SOC workflow: **collect → analyze → detect → alert → log.**

## 🎯 Why I Built This

During the course we covered core SOC concepts: log analysis, alerting pipelines,
threshold-based detection, and common attack signatures (scanning, DoS, brute force).

Instead of just describing these concepts, I wanted to **build something that actually
detects them in real traffic**, the same way a lightweight IDS/IPS sensor would sit at
the edge of a network and feed alerts into a SOC's monitoring pipeline. This project
demonstrates practical application of:

- **Traffic analysis** using Python + Scapy (packet-level inspection)
- **Sliding time-window detection logic** (a core technique in real IDS/SIEM rule engines)
- **Structured security logging**, which is exactly what SOC analysts rely on for
  triage and incident response
- **Threshold tuning**, since real detection rules always need calibration to reduce
  false positives — configurable in `config.py`

## ⚙️ How It Works

1. NetGuard inspects each packet's `IP`/`TCP`/`ICMP` layers.
2. For every source IP, it keeps a **sliding time-window** of recent activity
   (ports touched, ICMP packets sent, connection attempts per port).
3. If activity within the window crosses a configured threshold, an **alert** fires.
4. A **cooldown timer** prevents the same alert from spamming the log repeatedly for
   one ongoing event.
5. Alerts are logged to disk in JSON (default) or CSV — ready to be ingested by a
   dashboard, SIEM, or reviewed manually.

All thresholds live in `config.py` so detection sensitivity can be tuned without
touching the core logic — the same principle behind tunable detection rules in tools
like Snort or Suricata.

## 🚀 How To Run It

### 1. Install dependencies
```bash
pip install -r requirements.txt
```

### 2. Option A — Analyze a saved capture (no special privileges needed)
A synthetic demo capture generator is included, so you can test detection immediately:
```bash
python3 generate_demo_pcap.py          # creates sample_output/sample_capture.pcap
python3 netguard.py --pcap sample_output/sample_capture.pcap
```

### 3. Option B — Live monitoring (requires root/admin privileges)
```bash
sudo python3 netguard.py
# or specify an interface:
sudo python3 netguard.py --iface eth0
```

Press `Ctrl+C` to stop a live session; a summary of total alerts raised is printed.
